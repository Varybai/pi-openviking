# 宿主 MCP 连接与验证

用于当前宿主没有 OV 工具、需要添加连接、认证失败或状态不明确时。宿主可为 Pi、Claude Code、Codex 或其他支持 HTTP MCP 的 Agent。配置语法和凭据存储方式由该宿主决定。

## 发现已有连接

先使用宿主当前提供的 MCP 状态、工具发现或工具搜索入口。工具可能延迟加载，或通过 codemode 间接调用；顶层工具列表不完整不能单独证明未连接。

读取实际工具 schema，不要根据宿主名称猜测工具前缀。服务端短名称如 `find`、`search`、`read`、`add_resource` 可能被宿主添加命名空间。`lego_query` 等扩展能力只有目标服务提供时才可使用。

Pi 的 `/mcp` 和 `/ov-*` 是会话命令。`pi mcp list` 不加载扩展，因此它的结果不能单独验证本包动态注册的连接。其他宿主不使用这些 Pi 命令。

## 添加或修复连接

在已授权的配置范围内，先确定以下连接信息，再使用宿主文档或 CLI 帮助提供的正式配置入口：

| 连接信息 | 处理方式 |
|---|---|
| HTTP 基础地址 | 使用已确认地址，例如 `https://ov.example.com`；允许已确认的代理路径前缀 |
| MCP 地址 | 通常为基础地址加 `/mcp`；自定义路由以部署信息为准 |
| 认证 | 由服务要求决定；API key 模式使用对应目标服务的凭据 |
| 身份 | 服务要求时提供 account、user、peer；不要从另一环境复制身份值 |
| 作用范围 | 保持用户指定的项目或用户范围，保留其他 MCP 配置 |

OV 的 API key 连接常用 `Authorization: Bearer …`。身份头为 `X-OpenViking-Account`、`X-OpenViking-User` 和可选的 `X-OpenViking-Actor-Peer`。以实际服务认证要求为准；使用宿主的私密存储或环境变量引用机制，不把密钥写进共享项目配置。

不同宿主对环境变量插值和认证字段的语法不同。不要直接把 Pi profile JSON 或另一宿主的 `mcp.json` 复制过去。凭据只发送到已确认的目标服务。

仅安装此 Skill 的环境没有 `src/index.mjs`、`bin/pi-openviking.mjs` 或 Node 运行时依赖。它仍可通过宿主已经配置的 MCP 操作 OV。只有任务明确需要 Pi package 时才按 Pi 专用指南安装；不要为其他 Agent 安装 Pi 来弥补缺失连接。

新增环境变量需要出现在运行宿主的进程环境中。Agent 子 shell 的 `export` 不能改变父进程；按宿主机制重启后验证。缺少会话控制接口时，报告配置已保存及必要的重载操作，不把命令文本当作执行结果。

## 验证与排障

1. 核对实际生效的服务器地址、账号及配置来源。不要只检查期望配置文件。
2. 查看 MCP 连接状态并执行一次当前 schema 支持的只读调用，例如 `health`。
3. 小范围读取或检索任务指定资源，确认资源权限和可见性。

HTTP `/health` 成功但 MCP 失败时，检查 MCP 路由、认证、宿主连接配置和同名覆盖。MCP 成功但资源不可见时，检查身份、URI 和检索范围。不要因一次空结果重新部署 OV 或重复入库。

安装 Skill、发现 Skill 和 MCP 连接成功分别验证。报告具体停在哪一步；不预设服务端工具数量或数据总量。
